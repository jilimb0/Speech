## 1. Контекст и архитектурные вызовы

`Speech` — сервис распознавания речи и голосовых сообщений (Whisper API / локальные модели / Telegram Voice).
Критические риски до внедрения:
1. **Высокая стоимость и latency повторного распознавания:** Идентичные аудиозаписи или повторно пересланные голосовые отправлялись в Whisper API заново, расходуя деньги и задерживая ответ на 5–15 секунд.
2. **Зависание при деградации внешнего провайдера:** Без строгого таймаута обработка зависала при сбоях OpenAI / Groq / локального Whisper.

---

## 2. Реализованные архитектурные решения

- [x] **2.1. Дедупликация аудио по SHA-256 (`services/speech/src/speech-service.ts`)**
  - Метод `transcribeBuffer`: вычисление хеша аудио-буфера `SHA-256(audioBuffer + language + model)`.
  - Кэширование расшифрованного текста (TTL 7 дней). Повторные запросы возвращают результат мгновенно (<5 мс).

- [x] **2.2. Защита таймаутом и Full Jitter Retries**
  - Ограничение времени обращения к провайдеру распознавания до 30 000 мс через `AbortController`.
  - 3 попытки повтора с экспоненциальной задержкой и джиттером при получении статусов 429 (rate limit) или 503 от Whisper API.
