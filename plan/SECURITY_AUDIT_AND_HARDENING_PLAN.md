# План аудита и устранения уязвимостей безопасности: Speech (AI Speech Coach)

> **Текущий скор безопасности:** 70 / 100 (🟡 Средний уровень риска)  
> **Дата аудита:** Октябрь 2026  
> **Статус:** Требуется ужесточение проверок окружения и валидации медиа  

---

## 1. Обнаруженные уязвимости

### [P2] Потенциальный обход аутентификации через Dev-режим
* **Файл:** `apps/api/src/middleware/tma-auth.ts` (строки 30–40)
* **Механика проблемы:**
  В хуке аутентификации присутствует bypass для разработки:
  ```typescript
  const isDev = process.env.NODE_ENV === 'development' || process.env.DEV_MODE === 'true';
  if (isDev && (!initData || initData === 'dev')) {
    request.telegramUserId = DEV_TELEGRAM_USER_ID; // 387147568
    return;
  }
  ```
  Если на боевом сервере переменная `NODE_ENV` не будет явно задана в `production` (Node.js по умолчанию не принуждает `NODE_ENV=production`), любой запрос без заголовка или со значением `dev` автоматически получит права пользователя разработчика (`DEV_TELEGRAM_USER_ID`).
* **Потенциальный ущерб:** Доступ к сессиям и записям тренировок разработчика без авторизации.

### [P2] Валидация аудиофайлов перед передачей в Whisper
* **Файл:** `apps/api/src/bot/handlers/voice.ts`, `services/speech/`
* **Механика проблемы:**
  Голосовые сообщения и аудиофайлы передаются на транскрибацию. Необходимо строго проверять magic bytes (MIME-тип `audio/ogg`, `audio/wav`, `audio/mp4`) и размер аудиодорожки, чтобы исключить передачу некорректных бинарных данных, вызывающих зависание инференса Whisper.

### [P2] Защита от исчерпания бюджета AI-коуча (Cost-Spike DoS)
* **Файл:** `services/analysis/`
* **Механика проблемы:**
  Генерация отчетов и фидбека AI-коуча использует LLM API. Отсутствие жесткого лимита на количество анализов в сутки для бесплатного тарифа может привести к резкому росту расходов на API.

---

## 2. Пошаговый план устранения (Hardening Plan)

- [ ] **Шаг 1 (P1): Ужесточение проверки окружения в `tma-auth.ts`**
  - Разрешать dev bypass **только** при одновременном выполнении условий: `process.env.NODE_ENV === 'test'` или явном флаге `ALLOW_DEV_AUTH_BYPASS === 'true'`, и категорически блокировать bypass при `NODE_ENV === 'production'`.
  - При отсутствии `TELEGRAM_BOT_TOKEN` сервер должен немедленно завершать работу с ошибкой при старте, а не во время обработки первого запроса.

- [ ] **Шаг 2 (P2): Проверка аудиопотока и rate-limiting**
  - Валидировать длину аудио (максимум 120 секунд на одну запись в Mini App).
  - Установить жесткий лимит на количество вызовов AI-коуча (например, не более 3 бесплатных анализов в день без Pro-подписки через Telegram Stars).
